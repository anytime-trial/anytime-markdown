# 認知リズム（緩急）の規範

読み物寄りのドキュメントに**緩急**を設計するための規範。緩急を装飾ではなく、読者の認知モードの切替（観察 → 逡巡 → 断定 → 再観察）と、未回収の緊張の管理として扱う。`references/writing-standards.ja.md` が「破ってはいけない品質」を定めるのに対し、本ファイルは「読み進められる文章にする」ための設計を定める。

> 出典: k16shikano「認知リズムを生むための日本語ライティング規範」<https://gist.github.com/k16shikano/eb2929f13ed19c97188393d297be8432>（参照日: 2026-08-19）。gist のライセンス条項を確認のうえ、規範を参考に本プロジェクト向けに再構成した派生物である（逐語転載ではない）。同著者の「日本語技術文書の文章規範」を再構成した `references/writing-standards.ja.md` と対になる。

## 適用範囲と優先順位

- **主対象**: tech（技術解説記事）、manual の解説部、proposal / report の論述部。読者が通しで読む前提の文章に適用する。
- **対象外**: spec の機能仕様、test のテストケース表、plan のタスク一覧、review の指摘、および全 type の表・手順・API リファレンス。これらは参照して拾い読みされるため、緩急より一貫した書式を優先する。
- **衝突時は `writing-standards.ja.md` が優先する**。とくに「演出の抑制」「冗長の排除」「LLM っぽい表現の禁止」を、本ファイルの緩急を理由に緩めない。緊張は修辞（溜め、修辞疑問、決め台詞）ではなく、内容（未確定の判断、回収されていない問い、対象そのものの性質）で作る。

## 基本原理

- 緩急は情報量の増減ではなく、認知モードの切替として設計する。
- 文章は、常に少なくとも一つの**未回収の緊張**を開いておく。読み進める理由がそれである。
- 完成した結論を配るのではなく、考えながら進む当事者の声で書く。
- 拍・緊張・緩みの材料は、状況の側（対象の性質、観測した事実、判断の保留）からのみ取る。文章それ自体の進行を材料にしない。
- 装置は宣言するものではなく実現するものである。「ここで緊張を作る」と書かず、緊張が生じる書き方をする。
- **短文化バイアスの禁止**: 短く言い切れるのは、その文脈を読者と共有し終えたときに限る。共有前の圧縮は、読者に前を読み返させるだけになる。

## 文の拍

- 短文で足場を打ち、長めの文で流し、短文で止める（立てる → 流す → 止める）。
- 断定と逡巡を交互に置く。逡巡は弱さではなく仕掛けである。ただし `writing-standards.ja.md`「論証の厳密さ」のとおり、根拠なく主張を弱める緩和と、不確実性を保つ逡巡を混同しない。
- 転回点では「譲歩 → 転回 → 短い停止」の拍が効く。
- 長い断定文が三つ以上続いたら、短い足場か停止、または逡巡を挟む。

## 段落の密度波形

- 密な段落が二つか三つ続いたら、疎の段落を一つ置く。
- 具体に寄る段落と、意味づけで引く段落を交互に置く。
- 箇条書きは情報の圧縮だけでなく、地の文の連続を切る「間」としても使える。

## 冒頭の設計

冒頭の仕事は、最初の数文で未回収の緊張を一つ作ることである。使える型は次のとおり。

- 読者の実感から仮説へ進む。
- 読者へ直接問いかける。
- 確信を帯びた一般命題を置く。
- 語り手の思い込みを肯定的に書き切ってから、事実で崩す。
- 前章が残した問いを、当事者の言葉で言い直す。

予告や要約は、態度を帯びた一文か二文なら置いてよい。禁じるのは態度のない議題表（「本章では A、B、C を扱う」）である。読者が抱くであろう抵抗は、読者の言葉で先に言い、短く処理してから本題に入る。

## 節の入り方

- 「本節では〜を扱う」と宣言しない。
- 直前の節が残した違和感を、問いとして言い直す。
- 読者が当然抱く反問を、そのまま書く。
- 書き手の告白から入る。

理論、概念、引用は、読者の中に名前のない違和感を作ってから導入する。節と節をつなぐ橋は、前節の末尾ではなく次節の頭に置く。

## 列挙の着地

- 性質や分類を列挙したら、各項目を直前の具体的な場面へ一つずつ着地させる。列挙して次へ進まない。
- 着地の文体を均一にしない。同じ構文の繰り返しは、読者の注意を先に落とす。

## 問いの回収と結び

- 途中で立てた問いは明示的に回収する。
- 問いは半分ずつ返してよい。全部を一度に返すと、その先を読む理由が消える。
- 結びでは、抽象を読者がすでに持っている具体へ着地させる。
- 緊張は選んで閉じる。最後に一つだけ開いたまま残してよい。
- 二人称の呼びかけ、依頼、謙抑は、章の入口と結びでだけ機能する（`writing-standards.ja.md`「視点と語り」と同旨）。本文中盤に置かない。

## 緩みと駄文の判別

判定軸は一つだけ。**その文が更新するのは「状況」か、「文書」か**。

- **状況を更新する文**: 緩みとして残してよい。
- **文書を更新する文**: 原則として削除する。

駄文の典型（話題が本文自身で、状況の情報がゼロ）:

- 説明の見え方や執筆の予定への言及。
- 章の性格づけの言い直し。
- 本文の性格や範囲の宣言。
- 規範や装置の実況。
- 節末の進行予告。

良い緩みの典型（状況か、語り手の判断状態を更新する）:

- 思い込み（「うまくいっているに違いない」）。
- 判断の保留（「どこかの時点で整理は要るだろう」）。
- 感情の微差や後悔。
- 譲歩（「そうしたかった、とは思う」）。

文書について述べる文でも、次の四つの形は残してよい。

1. **反論処理**: 読者の誤読を「」で具体的に書き出して退ける。
2. **問いの設置と回収**: 問いの文そのものと、回収の文。
3. **読者への依頼や断り**: 「どうか〜と割り切って読んでほしい」。
4. **例の枠の開閉**: 架空の例や場面の枠を開き、閉じる操作。

## 執筆後の点検手順

1. **話題テスト**: 各文が状況を更新しているか、文書を更新しているかを判定する。文書側は削除するか書き換える。
2. **漏出テスト**: 本規範の語彙（「緊張」「回収」「答えの半分」「拍」など）が本文にそのまま現れていないか確認する。現れていれば削除し、装置を内容で実現し直す。
3. **緊張台帳**: 本文中で立てた問い、思い込み、約束を列挙し、それぞれの回収位置を指す。指せないものは、回収を書き足すか問い自体を削る。
4. **拍の点検**: 長い断定文が三つ以上連続している箇所を探し、短い足場か停止、または逡巡を挟む。
5. **境界の点検**: 二人称の呼びかけ、依頼、謙抑が本文中盤にないか確認する。あれば境界へ移すか削る。

## 症状から原因を引く

推敲の指示を受けたとき、症状から原因を引くための対応表。

| 症状 | 原因 |
| --- | --- |
| 全段落が同じ調子で疲れる | 文の拍がない |
| 読み進める気がしない | 未回収の緊張がない |
| 理論の節で急に温度が下がる | 理論を違和感より先に出している |
| 緩い文が弛んで見える | 緩みが文書更新（進行の実況）になっている |
| 章末が説教くさい | 抽象論のまま閉じている |
| 冒頭が事務的 | 態度のない議題表になっている |
