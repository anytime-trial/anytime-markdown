# 知見の経緯のデータ

`/timeline` ページの「知見の経緯」トラックが表示するデータの置き場。

## 正本と派生の関係

知識の正本は `<docsRoot>/report/daily-research/*.md`（日次技術調査レポート・2026-03-23〜08-07）と `<docsRoot>/report/weekly-research/*.md`（週次調査レポート・2026-03-29〜09-12）である。ここに置くのはそこからの派生物で、次の 3 層に分かれる。

| 層 | パス | 性質 |
| --- | --- | --- |
| テーマ辞書 | `themes.json` | 手で決める。抽出はここにある id しか使えない |
| 生データ | `raw/*.json` | レポート本文から抽出した結果。人（LLM）が読解した成果物なので手で直してよい |
| 成果物 | `insights.json` | `raw/` を機械的に正規化した生成物。**手で編集しない** |

隣の `../claude-code-releases/` が同じレポートから「リリース」を拾うのに対し、こちらは**リリースに紐づかない知見**——運用手法・技術動向・新語彙・エコシステムの変化——を拾う。両者は同じ日の同じレポートを別の観点で読んだ結果なので、内容が一部重なることはある。

## 再生成

```bash
npm run data:insights -w @anytime-markdown/web-app
```

`scripts/build-insight-timeline.ts` が `themes.json` と `raw/*.json` を読み、表記ゆれの吸収（影響度の 高/中/低 → high/medium/low）・同日同題の統合・日付昇順の並べ替えを行って `insights.json` を書き出す。正規化のロジックは純粋関数として `src/lib/insightTimeline/normalize.ts` にあり、`src/__tests__/insightTimelineNormalize.test.ts` が検証している。

スキーマ違反（`date` が `YYYY-MM-DD` でない、辞書に無いテーマ id、`themes` が空など）はスクリプトが例外で落とす。黙って落とさないのは、1 件の欠落が経緯では「その知見が無かった」ようにしか見えないため。

## テーマ辞書

テーマは**固定の id 集合**である。抽出時に自由記述を許すと「サブエージェント」「サブエージェント運用」「subagent」が別テーマになり、テーマ内の時系列＝経緯が成立しない。

辞書に無い概念が繰り返し現れたら、辞書へテーマを足してから抽出をやり直す。1 件のために足さない——テーマは束ねるための単位であって、分類のラベルではない。

## 新しいレポートを取り込む

抽出そのものは散文の読解を伴うため機械化していない。手順:

1. 対象レポートを読み、**リリースそのものではない知見**を拾う。1 レポートあたり 4〜8 件を目安にする
2. `raw/insights-<範囲>.json` として次の形で書き出す
3. 再生成コマンドを実行し、`insights.json` の差分と件数を確認する

```json
[
  {
    "date": "2026-08-07",
    "dateConfidence": "explicit",
    "category": "claude-code",
    "title": "200+ サブエージェント上限が撤廃される",
    "summary": "1 Workflow あたりのスポーン上限が実質撤廃され、1000 件の backstop だけが残った。同時実行 cap（16 スロット）は据え置き。",
    "themes": ["subagent"],
    "impact": "high",
    "sourceReport": "2026-08-07-daily-research.md",
    "sourceUrl": "https://code.claude.com/docs/en/changelog"
  }
]
```

- `category`: `claude-code`（Claude Code 活用の知見）/ `tech-trend`（AI・開発手法・ソフトウェア技術の動向）/ `vocabulary`（今日登場した新概念・新語彙）/ `ecosystem`（週次の Codex・Gemini・Ollama・利用モジュールの動向）
- `date`: 出来事の日付。本文に明記があれば `explicit`、無くレポート発行日で代用したなら `report-date`。画面ではこの区別を「日付は推定」として出す
- `title`: 体言止めにせず、**何がどうなったかが 1 行で分かる**ように書く（40 字以内）
- `summary`: 1〜2 文（120 字以内）。「何が分かったか」を書く。宣伝文とハイプ表現は使わない
- `themes`: 1〜2 個。辞書の id のみ。3 個以上付けない（どのテーマの経緯にも中心として並ばなくなる）
- `impact`: レポートの「影響度」表記に従う。判断できないときは `null`（自分で格付けしない）
- 同じ知見が複数レポートに現れてよい。統合は再生成側が行う（同じ日・同じタイトルなら 1 件へ畳み、出典を束ねる）

## 収録しないもの

- **リリースそのもの**（版数と変更点の列挙）。それは `../claude-code-releases/` の担当
- **経済ニュース**（決算・資金調達・株価・雇用統計）。技術セクション内に現れる企業財務の話も同じく外す
- 既報除外サマリー・完全性チェックなど、レポートの自己点検セクション

## 既知の限界

- 収録範囲は調査レポートの実施期間（日次 2026-03-23〜08-07、週次 2026-03-29〜09-12）に限られる
- 日次レポートは 2026-08-07 で止まっている。以降の知見は週次レポートだけが供給源になる
- 1 レポートあたりの抽出件数に上限を置いているため、**そのレポートが書いた知見の全量ではない**。経緯として意味を持つものを選んでいる
- **知見の `date` は出来事の日付なので、レポートの実施期間より前に出ることがある**（過去の調査結果や他ツールのリリースを後から取り上げた場合）。実測で 982 件中 18 件がレポート発行日より 1 か月以上前にあり、最も古いものは 2026-01-24 まで遡る
- 生成物は 982 件で、圧縮後およそ 100KB を `/timeline` が読み込む。これ以上増えるなら、年ごとの分割かテーマ単位の遅延読み込みへ切り替える分岐点になる
